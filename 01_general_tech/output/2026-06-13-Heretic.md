# Heretic 技術分析報告

## 1. 這個技術解決什麼問題？

**被解決的具體問題：** Transformer-based 語言模型（LLM）在 safety alignment（安全對齊）訓練後，會對被判定為「有害」的 prompt 產生拒絕回應（refusal），例如 "I cannot help with that"。Heretic 提供一個**全自動化**的方法，在不進行昂貴的 post-training（如 DPO/RLHF）的前提下，移除模型的 refusal 行為，同時最小化對模型原始能力的損害。

**模糊之處：** README 未明確定義「censorship」的邊界 — 是僅移除 overt refusal（顯式拒絕），還是也移除 covert noncompliance（隱式不遵從）。社群回報指出某些 Llama 基礎模型在 Heretic 處理後仍存在 covert noncompliance。

---

## 2. 這個問題為什麼會發生？（背景）

### 文章中明確提到的背景

- Instruct 模型經過 safety fine-tuning，學會對 harmful prompt 輸出 refusal 回應
- Arditi et al. (2024) 發現 refusal 行為由 residual stream 中的**單一方向**（single direction）中介
- 消除該方向可阻止 refusal，加入該方向可在 harmless prompt 上也引發 refusal
- 傳統 abliteration 需要人工選擇 layer、手動調整參數，且常導致模型能力顯著下降（Labonne 2024 報告 MMLU 等 benchmark 分數下降）

### 通用技術背景

- Transformer 的 residual stream 是各層元件（attention、MLP）寫入資訊的共享通道
- Safety alignment 通常透過 SFT + RLHF/DPO 實現，這些方法計算成本高
- 新一代模型（Gemma 3、Qwen 3、Phi 4、GPT-OSS）比舊模型更「密集」（dense），對粗粒度干預（如簡單正交化）更敏感，更容易造成能力損害
- 「Hydra Effect」（McGrath et al. 2023）：單層 ablation 會被其他層補償修復約 70% 的原始計算

## 3. 這個技術是如何解決該問題的？

### 核心機制：參數化 Directional Ablation

```
┌──────────────────────────────────────────────────┐
│                 Heretic 運作流程                    │
│                                                    │
│  1. 載入模型（支援 dense/MoE/multimodal/hybrid）    │
│       │                                            │
│       ▼                                            │
│  2. 收集 refusal directions                        │
│     • 對 harmful/harmless prompt 集做 forward pass │
│     • 提取每層 residual stream 的第一 token        │
│     • 計算 difference-of-means（每層一個方向向量）  │
│       │                                            │
│       ▼                                            │
│  3. TPE 自動優化（Optuna）                         │
│     • 參數空間：direction_index, max_weight,       │
│       max_weight_position, min_weight,             │
│       min_weight_distance（每組件獨立）             │
│     • 多目標：minimize refusals + minimize KL      │
│       │                                            │
│       ▼                                            │
│  4. Ablation（正交化）                              │
│     • 對 attn.o_proj / mlp.down_proj 的權重矩陣   │
│       移除 refusal direction 分量                  │
│       │                                            │
│       ▼                                            │
│  5. 輸出：LoRA adapter + 原模型                     │
└──────────────────────────────────────────────────┘
```

### 3.1 Refusal Direction 計算

對每個 transformer layer：
```
g = mean(residuals for "harmless" prompts)     // good direction mean
b = mean(residuals for "harmful" prompts)      // bad direction mean
r = b - g                                       // refusal direction (第 1 個 token)
refusal_directions[layer_i] = r
```

預設使用 `mlabonne/harmful_behaviors`（harmful prompts）和 `mlabonne/harmless_alpaca`（harmless prompts）。

### 3.2 參數化 Ablation Weight Kernel

```
Weight
  │
  │   max_weight ┤          ╱╲
  │              │         ╱  ╲
  │              │        ╱    ╲
  │   min_weight ┤───────╱      ╲───────
  │              │                          
  └──────────────┼────────────────────► Layer
       max_weight_position - min_weight_distance
                 
       max_weight_position + min_weight_distance
```

| 參數 | 說明 |
|------|------|
| `direction_index` | 使用的 refusal direction layer index；小數值時對相鄰兩層線性插值 |
| `max_weight` | 峰值 ablation 強度 |
| `max_weight_position` | 峰值所在 layer |
| `min_weight` | 基線 ablation 強度 |
| `min_weight_distance` | 從峰值到基線的過渡寬度 |

### 3.3 Ablation 操作

對每個 transformer component（attention out-projection、MLP down-projection）的權重矩陣：

```python
def ablate(weight_matrix, refusal_direction, weight):
    # 將 weight_matrix 對 refusal_direction 做正交化
    projection = weight_matrix @ refusal_direction
    orthogonal_component = projection * weight
    return weight_matrix - orthogonal_component
```

三種 row normalization 模式：
- `none`：直接 ablation（原始方法）
- `pre`：projected abliteration（先投影再 ablation）
- `full`：norm-preserving biprojected abliteration（low-rank SVD 保留 norm）

### 3.4 TPE 多目標優化（Optuna）

```python
study = optuna.create_study(
    directions=["minimize", "minimize"],  # 雙目標
    sampler=TPESampler()
)

def objective(trial):
    params = {
        "direction_index": trial.suggest_float("direction_index", ...),
        "max_weight": trial.suggest_float("max_weight", ...),
        ...
    }
    model = abliterate(base_model, params)
    refusals = count_refusals(model, test_prompts)
    kl_div = compute_kl_divergence(original_model, model, harmless_prompts)
    return refusals, kl_div  # Pareto 雙目標

study.optimize(objective, n_trials=200)
```

Pareto front 選擇策略：在 refusal count 接近 0 的 trial 中選 KL divergence 最低者。

### 3.5 三個設定檔差異

| 設定檔 | 用途 | 關鍵差異 |
|--------|------|---------|
| `config.default.toml` | 標準 refusal 移除 | `mlabonne/harmful_behaviors` vs `mlabonne/harmless_alpaca` |
| `config.nohumor.toml` | 移除模型的幽默風格 | `bad_prompts` 改用 `UnstableLlama/jokes`，refusal_markers 改為笑話相關字串（"haha", "lol", "dad joke" 等） |
| `config.noslop.toml` | 移除模型的文學 cliché（purple prose） | `bad_prompts` 使用 `llm-aes/writing-prompts` 並加上 cliché prefix，refusal_markers 為 "Eldoria", "ethereal", "tapestry" 等 cliché 詞彙 |

### 3.6 支援的模型架構

- 標準 dense（`self_attn.o_proj`, `mlp.down_proj`）
- Qwen3.5 MoE hybrid（`linear_attn.out_proj`）
- Qwen3 MoE（`mlp.experts[i].down_proj`）
- Phi-3.5-MoE（`block_sparse_moe.experts[i].w2`）
- LFM dense/transformer blocks
- Granite MoE Hybrid（`shared_mlp.output_linear`, `moe.experts[i].output_linear`）
- 多模態模型（`AutoModelForImageTextToText`）

### 3.7 實驗結果（gemma-3-12b-it）

| Model | Refusals (harmful) | KL Divergence (harmless) |
|-------|-------------------|--------------------------|
| google/gemma-3-12b-it (original) | 97/100 | 0 (by definition) |
| mlabonne/gemma-3-12b-it-abliterated-v2 | 3/100 | 1.04 |
| huihui-ai/gemma-3-12b-it-abliterated | 3/100 | 0.45 |
| **p-e-w/gemma-3-12b-it-heretic (Heretic)** | **3/100** | **0.16** |

### 3.8 關鍵技術創新

1. **Float `direction_index`**：非整數值時對相鄰兩層 refusal direction 做線性插值，解鎖比單層更豐富的方向空間
2. **Per-component 獨立參數**：`attn.o_proj` 和 `mlp.down_proj` 各自有獨立的 weight kernel
3. **靈活 weight kernel**：支援梯形/三角形 weight 分佈，非恆定 ablation 強度
4. **TPE 多目標自動優化**：co-minimize refusal count + KL divergence，無需人工調參
5. **LoRA adapter 架構**：不直接修改權重，支援快速 trial 間 reset
6. **三種 row normalization**：`none` / `pre` / `full`，滿足不同模型架構需求

## 4. 是否存在解決類似問題的其他技術 / 框架 / 思考方式？

### DA 表（Decision Analysis）

| 技術名 | 技術解法 | 技術使用前提 | 技術使用副作用 | 技術使用預期效果 |
|--------|---------|-------------|---------------|----------------|
| **AutoAbliteration** (Maxime Labonne) | 基於 abliteration 的自動化工具，使用 Hugging Face Transformers | 需安裝 Hugging Face 生態；支援的模型架構有限 | 僅支援簡單權重 ablation；無法自動調參；benchmark 退化較明顯（MMLU 等分數下降） | 基本的自動化 abliteration |
| **abliterator.py** (FailSpy) | Python 腳本實現原始 Arditi 方向性 ablation | 需手動指定 layer 與參數 | 人工調參耗時；固定 weight；僅支援基本 transformer | 單層 ablations 的快速實驗 |
| **ErisForge** (Tsadoq) | GUI 工具輔助 abliteration 參數選擇 | 需安裝 GUI 環境；需對 abliteration 有一定理解 | GUI 操作可能不夠精確；缺乏自動優化；對新模型支援較慢 | 視覺化輔助的 ablation 參數探索 |
| **deccp** (AUGMXNT) | 基於 contrastive activation addition 的去審查方法 | 需理解 activation engineering 概念 | 不同於 abliteration 的正交化方法；對不同模型的穩定性不一 | 另一種 activation engineering 途徑 |

### 各方案切入點差異

| 方案 | 核心切入點 |
|------|-----------|
| **Heretic** | **全自動化** + TPE 多目標優化 + float direction_index + per-component 獨立 weight kernel + LoRA adapter 架構 |
| **AutoAbliteration** | 基於原始 abliteration 論文的自動化，缺乏進階優化 |
| **abliterator.py** | 腳本級別的手動實驗工具 |
| **ErisForge** | GUI 輔助的視覺化工具 |
| **deccp** | 不同技術路線（contrastive activation addition 而非正交化 ablation） |
