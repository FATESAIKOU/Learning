# Tolaria — 技術分析報告

## 1. 這個技術解決什麼問題？

**被解決的具體問題：** 個人知識庫管理（PKM）中，**資料所有權、AI agent 可讀性、跨工具可攜性三者之間的矛盾**。現有 PKM 工具（Obsidian、Notion、Logseq 等）將資料鎖在特定 app 或雲端服務中，匯出困難或格式專有；AI agent（Claude Code、Codex CLI 等）需要能直接讀寫知識庫，但多數工具不提供標準化 MCP 介面；使用者需要在離線、無帳號、無訂閱的條件下管理大量筆記（10,000+），且保有完整版本歷史。

**模糊之處：** README 未明確說明「AI-first but not AI-only」的具體邊界——哪些功能依賴 AI agent、哪些是純本地操作。

---

## 2. 這個問題為什麼會發生？（背景）

### 文章中明確提到的背景

| 因素 | 說明 |
|------|------|
| 作者自身需求 | Luca（[@lucaronin](http://x.com/lucaronin)）管理 10,000+ 筆記的 vault，現有工具無法滿足其需求 |
| 現有工具缺陷 | 雲端鎖定（Notion）、缺乏 AI agent 整合、缺乏 git 版本控制 |
| AI agent 崛起 | Claude Code、Codex CLI、Gemini CLI 等需要透過 MCP 存取知識庫，但多數工具未實作 MCP server |

### 通用技術背景（文章中未明確提及，但構成問題脈絡）

- **PKM 工具碎片化**：Obsidian 用檔案夾但缺乏原生 git 整合與 AI agent MCP；Notion 是專有雲端格式；Logseq 是 outliner 模式；Foam/Dendron 是 VS Code 插件，非獨立 app
- **資料主權意識**：使用者日益要求 files-first、offline-first、無 vendor lock-in
- **桌面 app 復興**：Tauri v2 讓跨平台桌面 app 能以 web 前端 + Rust 後端的方式高效建構
- **MCP 標準化**：Anthropic 於 2024 年底提出 MCP（Model Context Protocol），成為 AI agent 與外部工具間的標準協議

### 3.1 Files-first / Git-first / Offline-first 的實作方式

| 原則 | 實作方式 |
|------|---------|
| **Files-first** | 所有筆記是純 `.md` 檔案，存在 vault 目錄的根層（flat structure）。無資料庫。App 只讀寫檔案，不擁有資料。`VaultEntry` 是從檔案解析出的記憶體內表示，可隨時從檔案系統重建。 |
| **Git-first** | 每個 vault 是一個 git repo。Git 操作全部透過 shell out 到系統 `git` CLI（非 libgit2）。支援 commit、pull/push、conflict resolution、AutoGit（閒置自動 checkpoint）、Pulse View（git activity feed）。非 git vault 仍可正常編輯，只是 git 功能隱藏。 |
| **Offline-first** | 無帳號、無訂閱、無雲端依賴。快取存在 `~/.laputa/cache/`（vault 外部）。所有操作本地完成。Git remote 為可選項。 |

**三層資料表示與不變量**：
```
Filesystem (.md) ──scan_vault_cached()──► Cache (~/.laputa/cache/) ──useVaultLoader──► React State (VaultEntry[])
       ▲                                                                                      │
       └────────────────────────── write via Tauri IPC first ─────────────────────────────────┘
```

不變量：
1. **Disk-first writes**：所有變更先寫入磁碟，再更新 React state
2. **Optimistic UI with rollback**：必要時先更新 UI，寫入失敗則復原
3. **Cache is disposable**：`reload_vault` 會刪除快取後重新掃描
4. **Filesystem wins**：任何分歧以檔案系統為準

### 3.2 "Types as lenses, not schemas" 的實作方式

Type 是**導航輔助，而非強制 schema**：

- Type 由 frontmatter 中的 `type:` 欄位決定（例如 `type: Project`），**絕不從資料夾位置推斷**
- 所有筆記存在 vault 根層，不分資料夾（flat structure）
- 無必要欄位、無驗證、無強制
- Type document（`type: Type` 的筆記）定義該 type 的 icon、color、order、template、sort 等**顯示屬性**
- Type document 上的自訂屬性定義 instance 的「期望形狀」，但**既存 instance 不會被自動修改**；Inspector 只顯示灰色 placeholder 提示缺少的屬性
- 系統屬性以 `_` 前綴（如 `_icon`、`_color`、`_width`），對使用者隱藏但可透過 raw editor 編輯

### 3.3 AI 整合的實作方式

Tolaria 支援 **6 種 CLI AI agent** 作為子程序（subprocess）執行，並提供 **MCP server** 讓外部 AI 工具存取 vault：

#### Agent 架構

```
User (AiPanel)
  │ sendMessage(text, references)
  ▼
useCliAiAgent (Frontend)
  │ buildContextSnapshot(activeNote, linkedNotes, openTabs)
  ▼
ai_agents.rs (Rust) ──pick adapter──► Claude CLI / Codex CLI / OpenCode / Pi / Gemini / Kiro
  │                                      │
  │ spawn with MCP-enabled config        │ MCP tool calls
  ▼                                      ▼
Normalized stream (NDJSON/JSONL/JSON)   MCP Server (search_notes, read_note, edit_note…)
  │
  ▼
AiPanel: TextDelta → accumulate, ThinkingDelta → reasoning block,
         ToolStart → AiActionCard, ToolDone → update card, Done → reveal
```

#### 各 Agent 的 Safe / Power User 模式

| Agent | Safe 模式 | Power User 模式 |
|-------|----------|----------------|
| **Claude Code** | file/search/edit tools only | 加入 Bash，`--allowedTools` 預先核准 |
| **Codex CLI** | `--sandbox read-only --ask-for-approval untrusted exec` | `--sandbox workspace-write --ask-for-approval never exec` |
| **OpenCode** | 拒絕 bash 與外部目錄 | 允許 bash，仍拒絕外部目錄 |
| **Pi** | 暫態 MCP config，不承諾 shell | 同 Safe（暫態 MCP，prompt 不承諾 shell） |
| **Gemini CLI** | `auto_edit` + `tools.exclude=["run_shell_command"]` | `yolo` 模式（對信任的暫態 MCP） |
| **Kiro** | `--no-interactive --trust-all-tools`，stdin 傳 prompt | 同 Safe |

#### AGENTS.md 機制

- `AGENTS.md` 是 vault 層級的 canonical AI 指引檔
- `CLAUDE.md` 是相容性 shim，指向 `AGENTS.md`
- `GEMINI.md` 是選擇性 Gemini CLI shim
- Agent system prompt 會指示 agent 先讀 vault 的 `AGENTS.md`，再搜尋 bundled Tolaria docs

### 3.4 MCP Server 整合

MCP server（`mcp-server/`，Node.js）提供 **15 個 tools** 給外部 AI 客戶端：

| 類別 | Tools |
|------|-------|
| **讀取** | `open_note`, `read_note`, `list_notes`, `search_notes`, `list_vaults`, `vault_context` |
| **寫入** | `create_note`, `append_to_note`, `edit_note_frontmatter`, `delete_note`, `link_notes` |
| **UI 控制** | `ui_open_note`, `ui_open_tab`, `ui_highlight`, `ui_set_filter` |

**雙傳輸層**：
- **stdio**：標準 MCP transport，供 Claude Code / Cursor / Gemini CLI / OpenCode 使用
- **WebSocket**：Port 9710（Tool bridge）+ Port 9711（UI bridge）

**自動註冊目標**：
- `~/.claude.json` / `~/.claude/mcp.json`（Claude Code）
- `~/.gemini/settings.json`（Gemini CLI）
- `~/.cursor/mcp.json`（Cursor）
- `~/.config/mcp/mcp.json`（generic MCP clients）
- `~/.config/opencode/opencode.json`（OpenCode）

### 3.5 Editor 與 Command Palette 的 Keyboard-first 設計

**Editor**：
- BlockNote（rich text）+ CodeMirror 6（raw markdown）雙模式
- 自訂 wikilink inline content type（`[[target]]` 語法）
- 支援 Mermaid 圖表、tldraw 白板、KaTeX 數學、Shiki 程式碼高亮
- 無 tab 式多筆記（ADR-0003），改用 Cmd+[/] 導航歷史

**Command Palette**（Cmd+K）：
- 集中式命令註冊表
- 命令的可用性根據當前 selection state 動態決定
- macOS browser-reserved chords 透過 `tauri-plugin-prevent-default` 解除攔截

### 3.6 資料模型

```
VaultEntry (核心資料型別)
├── path: string                 // 絕對檔案路徑
├── title: string                // 從 H1 或檔名 fallback
├── isA: string | null           // type: frontmatter 的值
├── aliases: string[]            // wikilink 解析別名
├── belongsTo: string[]          // 父關係 (belongs_to:)
├── relatedTo: string[]          // 橫向關係 (related_to:)
├── relationships: Record<string, string[]>  // 所有含 wikilink 的 frontmatter 欄位
├── outgoingLinks: string[]      // 內文中的 [[wikilinks]]
├── status: string | null        // Active, Done, Paused, Archived, Dropped
├── properties: Record<string, VaultPropertyValue>  // 自訂純量屬性
└── modifiedAt / createdAt / fileSize / wordCount / snippet
```

### 3.7 關鍵技術創新

1. **動態 Relationship 偵測（ADR-0010）**：不 hardcode 關係欄位名稱，Rust parser 掃描所有 frontmatter keys
2. **Crash-safe Rename Transaction**：兩階段 commit 機制
3. **Progressive Vault Loading**：大 vault 先渲染殼層再背景索引
4. **Git-based Incremental Cache**：三層快取（Cache Hit / Incremental Update / Full Scan）
5. **Multi-Window Note Editing**：筆記可在獨立 Tauri window 開啟
6. **Mounted Workspaces**：多 vault unified graph 與 cross-workspace wikilink
7. **Deep Links**（`tolaria://`）：自訂 URL scheme 導航
8. **無 Global State Management**：不使用 Redux/Context，props-down/callbacks-up

## 4. 是否存在解決類似問題的其他技術 / 框架 / 思考方式？

### DA 表（Decision Analysis）

| 技術名 | 技術解法 | 技術使用前提 | 技術使用副作用 | 技術使用預期效果 |
|--------|---------|-------------|---------------|----------------|
| **Obsidian** | 本地 Markdown vault + 社群插件生態系 + 自訂語法（wikilinks、callouts） | 需安裝 Obsidian app；跨裝置同步需 Obsidian Sync 或第三方方案 | 無原生 git 整合；無內建 MCP server；插件品質不一；資料雖是本地檔案但 app 體驗依賴插件 | 高度可自訂的 PKM 環境，豐富的圖譜視圖，龐大社群 |
| **Notion** | 雲端區塊式資料庫 + 多種 view（table、board、calendar） | 需網路連線與帳號；資料存於 Notion 伺服器 | 專有格式，匯出為 Markdown/CSV 會遺失結構；離線能力有限；無 git 版本控制；API 非 MCP 標準 | 彈性的資料庫視圖，團隊協作，豐富的模板生態 |
| **Logseq** | 本地 Markdown/Org-mode outliner + 雙向連結 + 白板 | 需安裝 Logseq app；以每日日誌為核心工作流 | Outliner 模式強制階層結構；非傳統自由格式筆記；git 整合需手動；無原生 MCP server | 大綱式知識管理，每日日誌驅動的工作流，雙向連結 |
| **Foam / Dendron** | VS Code 插件，以 Markdown 檔案 + wikilinks 建立知識圖譜 | 需安裝 VS Code；Dendron 有嚴格的階層式檔名約定 | 依附 VS Code 生態，非獨立 app；Foam 維護較少；Dendron 的階層命名約定學習曲線高；無原生 MCP | 開發者友善的 PKM（已在 VS Code 內），Dendron 的階層式導航 |
| **Tolaria** | Tauri 桌面 app + Rust 後端 + 純 Markdown vault + git 原生整合 + MCP server + 多 CLI AI agent 支援 | 需安裝桌面 app（macOS/Windows/Linux）；需系統 git CLI | Flat vault 結構（所有筆記在根層）；無插件系統；AGPL-3.0 授權；無 mobile app（iOS prototype 階段） | 離線、無鎖定的知識庫管理，AI agent 深度整合，git 版本控制，鍵盤驅動操作 |

### 各方案切入點差異

| 方案 | 核心切入點 |
|------|-----------|
| **Obsidian** | 以**插件生態**與**圖譜視覺化**為核心，讓使用者自行組裝 PKM 環境 |
| **Notion** | 以**雲端資料庫**與**多種視圖**為核心，強調彈性結構與團隊協作 |
| **Logseq** | 以**outliner 模式**與**每日日誌**為核心，強制階層式思考 |
| **Foam/Dendron** | 以**VS Code 生態**為核心，讓開發者在熟悉環境中管理知識 |
| **Tolaria** | 以 **AI agent 深度整合** + **git 原生版本控制** + **MCP 標準介面** 為核心，將知識庫定位為 AI 可讀寫的結構化資料源 |
