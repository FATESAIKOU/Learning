# iptv-org/iptv 技術分析

> 調研標的：[`iptv-org/iptv`](https://github.com/iptv-org/iptv)（126k stars / 6.9k forks / 34,143 commits，授權 CC0 / Unlicense）
> 調研日期：2026-06-20

---

## 1. 這個技術解決什麼問題？

**核心問題**：全球「公開可播放的 IPTV 頻道」散落在各電視台、CDN、 aggregator 平台（Pluto TV / Samsung TV Plus / 各國公共電視等），缺乏一個「統一、可程式化、機器可讀」的入口；使用者若想用 VLC / mpv / Kodi 等任意播放器看免費直播，必須自行收集逐台 stream URL，且 URL 經常失效、重複、品質不一。

**被解決的具體問題（可量化）**：

| 子問題 | 量化指標 |
|---|---|
| 來源分散 | 目前收錄來自 240+ 國家/地區、約 8,000+ 頻道、25+ 語言分類 |
| URL 失效 | 每日 0:00 UTC 自動巡檢、自動移除 broken stream |
| 機器可讀性差 | 統一輸出 `#EXTM3U` / `#EXTINF` 格式，可被任何 M3U 播放器解析 |
| 分類需求多樣 | 提供 by-category / by-language / by-country / by-subdivision / by-city 五種分類視圖 |
| 元資料四散 | 頻道 metadata（名稱、logo、分類、語言、播送區域）從 database repo 統一載入 |
| 法律模糊 | 明確聲明「不儲存影音檔，僅收錄指向公開 URL 的連結」，並提供 blocklist 與版權申訴流程 |

**模糊點**：
- 專案不驗證「公開性」的法律判斷是否來自版權持有者，僅以「to the best of our knowledge have been intentionally made publicly by the copyright holders」自我聲明；實際上多數 URL 為使用者提交，版權狀態由 issue 申訴被動處理。
- 專案自 2024-01-30 起停止收錄 NSFW（XXX）頻道（issue #15723），分類列表中 `XXX` 與 `Interactive` 顯示 0 頻道，代表「政策性排除」而非「無此類內容存在」。

## 2. 這個問題為什麼會發生？（背景）

### 文章中明確提到的背景

| 背景 | 說明 |
|---|---|
| IPTV 協定本質 | IPTV = 透過 IP 網路傳遞電視，播放端只需取得 stream URL（HLS `.m3u8` / RTMP / RTSP / SRT / UDP…），播放器即可解碼 |
| 頻道來源多樣化 | 電視台官方 CDN、Pluto TV、Samsung TV Plus、AMAGI、Infomaniak 等 aggregator 各自發布免費直播 |
| URL 易失效 | 串流來源可能改址、加 geo-block、轉為付費、或被下架 |
| GitHub Pages 部署 | 專案把產物 m3u 部署到 `https://iptv-org.github.io/iptv/`，純靜態檔案，免維護播放伺服器 |

### 通用技術背景（文章未明說）

| 背景 | 說明 |
|---|---|
| M3U 是播放清單事實標準 | `#EXTM3U` 標頭 + `#EXTINF` 描述 + URL，是 Winamp 時代遺留至今的播放清單格式，被 VLC / mpv / FFmpeg / IPTV 機上盒廣泛支援 |
| HLS 為主流傳輸 | `.m3u8` 是 HLS 的 manifest，內含 segment 清單；播放器拉取後做 adaptive bitrate |
| EPG（電子節目表）需獨立提供 | 頻道清單只給 stream URL，節目表需另由 `iptv-org/epg` repo 抓取 XMLTV 格式 |
| Xtream Codes 伺服器被排除 | Xtream Codes 是常見的 IPTV 盜版 panel 軟體，URL 形如 `http://host:25461/user/pass/channelId`，專案明文拒收以規避法律風險 |
| 聯邦式 repo 拆分 | iptv-org 將專案拆成 7+ repo：`iptv`（清單）/ `database`（metadata）/ `api`（JSON API）/ `epg`（節目表）/ `awesome-iptv`（資源）/ `sdk`（TS SDK），各自獨立部署 |

## 3. 這個技術是如何解決該問題的？

### 3.1 整體架構

```
┌─────────────────────────────────────────────────────────────────────┐
│  iptv-org/iptv repo (本專案)                                        │
│                                                                      │
│  streams/          ← 人工 + PR 提交的「內部原始清單」(按國家分檔)     │
│  scripts/          ← TypeScript 自動化腳本 (tsx 執行)                │
│  .github/workflows/  ← GitHub Actions 每日自動排程                   │
│                                                                      │
│         ┌──────────── api:load ────────────┐                        │
│         │  從 iptv-org/api 拉最新 metadata │                        │
│         └──────────────┬───────────────────┘                        │
│                        ▼                                              │
│  ┌──── playlist:update ────┐  處理已核可的 issue 請求                │
│  │ playlist:format         │  URL 正規化 / 去重 / 排序              │
│  │ playlist:lint (m3u-linter)  語法檢查                              │
│  │ playlist:validate       │  id 與 link 錯誤檢查                    │
│  │ playlist:generate        │  產出對外 public m3u (category/lang/   │
│  │                          │  country/subdivision/city)             │
│  │ playlist:export          │  輸出 JSON 給 api repo                 │
│  │ readme:update            │  更新 PLAYLISTS.md                    │
│  └────────────┬─────────────┘                                       │
│               ▼                                                      │
│      GitHub Pages (iptv-org.github.io/iptv/)                         │
│      index.m3u / index.category.m3u / countries/xx.m3u ...            │
└─────────────────────────────────────────────────────────────────────┘
        ▲                          ▲
        │                          │
   iptv-org/database         iptv-org/api
   (頻道 metadata CSV)        (對外 JSON API)
```

### 3.2 資料模型

**內部 streams 檔（`streams/<country>.m3u`）** 是唯一的人工編輯源頭，格式：

```
#EXTM3U
#EXTINF:-1 tvg-id="STREAM_ID",STREAM_TITLE (QUALITY) [LABEL]
STREAM_URL
#EXTVLCOPT:http-referrer=...
#EXTVLCOPT:http-user-agent=...
```

| 欄位 | 必填 | 規則 |
|---|---|---|
| `tvg-id` | 否 | `<channel_id>` 或 `<channel_id>@<feed_id>`，對應 database repo 的 channel id |
| `STREAM_TITLE` | 是 | 不可含 `,` `[` `]` |
| `QUALITY` | 否 | `2160p` / `1080p` / `720p` … |
| `LABEL` | 否 | `Geo-blocked` 或 `Not 24/7` |
| `STREAM_URL` | 是 | 支援 HTTPS/HTTP/MMS/MMSH/RTSP/RTMP/SRT/RTP/UDP |

實例（`streams/tw.m3u`）：
```
#EXTINF:-1 tvg-id="EBCNews.tw@SD",EBC News (東森新聞台) (1080p) [Not 24/7]
http://seb.sason.top/sc/dsxw_fhd.m3u8
```

### 3.3 自動化流水線（`package.json` scripts）

| 指令 | 對應檔案 | 作用 |
|---|---|---|
| `api:load` | `scripts/commands/api/load.ts` | 從 `iptv-org/api` 拉最新頻道/串流資料 |
| `playlist:format` | `playlist/format.ts` | URL 正規化、去重、移除無效 id、依頻道名/畫質/標籤排序 |
| `playlist:update` | `playlist/update.ts` | 處理已核可的 GitHub issue 請求（add/edit/remove） |
| `playlist:lint` | `m3u-linter -c m3u-linter.json` | m3u 語法靜態檢查 |
| `playlist:validate` | `playlist/validate.ts` | 檢查 id 與 link 錯誤 |
| `playlist:test` | `playlist/test.ts` | 實際連線測試每條 URL，輸出狀態表（OK / HTTP_FORBIDDEN / FFMPEG_STREAMS_NOT_FOUND…），可加 `--fix` 自動刪除壞連結 |
| `playlist:generate` | `playlist/generate.ts` | 依 category/language/country/subdivision/city 重新組合 public m3u |
| `playlist:export` | `playlist/export.ts` | 產 JSON 回饋給 `iptv-org/api` |
| `readme:update` | `readme/update.ts` | 重產 `PLAYLISTS.md` |

### 3.4 GitHub Actions 工作流

| Workflow | 觸發 | 執行順序 |
|---|---|---|
| `check` | pull_request | `api:load` → `playlist:check` → `playlist:validate`，錯則擋 PR |
| `format` | 手動/事件 | `api:load` → `playlist:format` → `playlist:lint` → `playlist:validate` |
| `update` | 每天 0:00 UTC | `api:load` → `playlist:update` → `playlist:lint` → `playlist:validate` → `playlist:generate` → `playlist:export` → `readme:update`，成功後部署到 GitHub Pages |

### 3.5 對外產物（消費端視角）

| 進入點 | URL 模式 | 用途 |
|---|---|---|
| 全域 | `https://iptv-org.github.io/iptv/index.m3u` | 全部頻道 |
| 分類 | `index.category.m3u` 或 `categories/<cat>.m3u` | 依類型（News/News 967 / Sports 412 / Movies 608…） |
| 語言 | `index.language.m3u` 或 `languages/<iso3>.m3u` | 依語言（English 2471 / Spanish 1949 / Chinese 209…） |
| 國家 | `index.country.m3u` 或 `countries/<iso>.m3u` | 依播送國 |
| 一級行政區 | `subdivisions/<iso-xxx>.m3u` | 如 `us-ca` / `ar-b` |
| 城市 | `cities/<geonameid>.m3u` | 最細粒度 |

**使用方式**：把任一 URL 貼進 VLC 的 Network Stream 即可。

### 3.6 貢獻流程（閉環）

```
使用者填 GitHub Issue 表單
  ├─ add    → 核可後下次 update 併入
  ├─ edit   → 改 tvg-id
  ├─ report → 通報壞連結
  └─ remove → 版權申訴（限版權方），核可後加入 database blocklist

維護者：PR 也可直接改 streams/*.m3u，CI 會跑 check workflow
```

### 3.7 關鍵設計約束

- **不收 Xtream Codes**：URL 形如 `host:25461/user/pass/id`，可由 `panel_api.php` 測試辨識，整個面板皆盜版來源，排除以降低法律風險。
- **不自架播放伺服器**：純靜態 GitHub Pages，所有 stream 皆指向第三方原始伺服器。
- **不儲存影音**：repo 內只有文字清單，DMCA 須向實際 hosting 主機申訴。
- **不收 NSFW**：2024-01-30 起政策性排除。
- **blocklist 機制**：被申訴移除的頻道寫入 `database/data/blocklist.csv`，避免未來再被加入。

## 4. 是否存在解決類似問題的其他技術 / 框架 / 思考方式？

### 4.1 同類/替代方案 DA 表

| 技術名 | 技術解法 | 技術使用前提 | 技術使用副作用 | 技術使用預期效果 |
|---|---|---|---|---|
| **自架 Jellyfin + Live TV M3U 插件** | 自架 media server，匯入外部 m3u 並內建 EPG 對應 | 需自有伺服器、頻寬 | 需自行維護伺服器與更新清單 | 私人一站式觀看 + 錄影 + 轉檔，清單失效需手動補 |
| **xTeVe / tvheadend + iptv-org 清單** | 把 iptv-org m3u 當作「訊號源」餵給 IPTV proxy，再透過 HDHR 協定餵給 Plex/Emby | 需常駐主機、Docker | 壞連結會使頻道黑屏，需定期重拉 | 把雲端 m3u 偽裝成有線電視訊號，相容於現有 DVR |
| **EPG-for-Free / iptv-org/epg** | 獨立抓 XMLTV 節目表，與 iptv-org 清單併用 | 需另抓 epg xml，播放器需支援 XMLTV | 節目表只覆蓋部分頻道 | 讓 m3u 播放器顯示節目表 |
| **手動維護私有 m3u（如 awesome-iptv 列表）** | 自行收集 stream URL 存成單一 m3u | 需自行驗證 URL | URL 易失效、無自動化巡檢 | 完全可控、可收錄 iptv-org 排除的內容 |
| **Xtream Codes panel（盜版 IPTV）** | 商業化 panel 軟體聚合付費頻道盜播 | 付費訂閱、法律灰色 | 法律風險、服務隨時被斷 | 取得付費頻道，但被 iptv-org 明文拒收 |

### 4.2 切入點差異

| 維度 | iptv-org/iptv | Jellyfin 自架 | tvheadend proxy | iptv-org/epg | 私有 m3u | Xtream Codes |
|---|---|---|---|---|---|---|
| **核心定位** | 眾包式公開清單聚合 | 自架媒體伺服器 | m3u → HDHR 轉接器 | 節目表補完 | 個人維護清單 | 盜版聚合 |
| **自動化程度** | 每日 CI 全自動 | 半自動 | 半自動 | 每日 CI | 全手動 | panel 維護 |
| **是否儲存影音** | 否（純文字） | 否（轉發） | 否（轉發） | 否（XMLTV 文字） | 否 | 是（部分） |
| **法律風險** | 低（只存連結、有 blocklist） | 取決於來源 | 取決於來源 | 低 | 自負 | 高 |
| **EPG 支援** | 另由 epg repo 提供 | 內建對應 | 透過 epg | 本身即 EPG | 需自找 | 內建 |
| **取得門檻** | 貼網址即可 | 需架伺服器 | 需架伺服器 | 貼網址即可 | 需自行收集 | 需付費 |
| **頻道覆蓋** | 公開免費頻道為主 | 不限 | 不限 | 公開頻道 | 自選 | 含付費盜播 |
| **失效處理** | CI 自動移除 | 需手動 | 需手動 | CI 自動 | 需手動 | 業者維護 |

### 4.3 取捨結論

- 想要「零部署、零維護、開箱即用」→ 直接消費 iptv-org GitHub Pages。
- 想要「DVR / 錄影 / 私人圖書館」→ Jellyfin/tvheadend 上游可接 iptv-org 清單。
- 想要「節目表」→ 額外接 `iptv-org/epg`。
- 想要「收錄被排除的內容（NSFW / 付費盜播）」→ 必須自管私有清單或用 Xtream Codes，但 iptv-org 不會收錄、法律風險自負。

## 附錄：快速使用

```bash
# 在 VLC 貼入全域清單
https://iptv-org.github.io/iptv/index.m3u

# 只要台灣頻道
https://iptv-org.github.io/iptv/countries/tw.m3u

# 只要新聞
https://iptv-org.github.io/iptv/categories/news.m3u

# 用 mpv 命令列播放
mpv https://iptv-org.github.io/iptv/countries/tw.m3u --playlist=/dev/stdin

# 本地 clone 並測試某國清單是否可用
git clone https://github.com/iptv-org/iptv
cd iptv && npm install   # postinstall 會自動跑 api:load
npm run playlist:test streams/tw.m3u
```
