# Maigret-C2-UserQA追加誰的什麼問題與發生背景.md

## 狀況理解

使用者回饋：第一版分析報告的 §1（解決什麼問題）與 §2（背景）寫得過於技術化、未明確回答「誰在用」「什麼痛點」「為什麼會演變到需要這工具」。使用者用「我還是不懂」表達理解斷層，屬 AGENTS.md 定義的質問型句構，觸發 §5 User Q&A。

理解要點：
- 需補上「使用者光譜」（誰在用）
- 需把「被解決的問題」拆成可理解的痛點鏈
- 需把背景拆成「需求側（OSINT 興起）」與「供給側（API 關閉、反爬升級）」
- 需區分文章明說 vs. 通用背景

## 其中的決斷點

| 意思決定面向 | 可選選項條列 | 選擇結果 | 選擇理由 |
|---|---|---|---|
| Q1 與 Q2 是否合併 | (a) 合併為單一 QA (b) 拆為兩題 | 拆為兩題 | AGENTS.md 規定「同一輪對話含多個子問題時，拆成多個獨立 QA，不可合併」；使用者問句含「誰的什麼問題」與「發生背景」兩個子問題 |
| 「誰在用」的呈現方式 | (a) 純文字列舉 (b) 表格含使用者類型/原因/範例 | 選 (b) | AGENTS.md 要求盡量用表格強化心智模型；範例欄位讓使用者具體對照自身情境 |
| 痛點鏈呈現 | (a) 條列 (b) ASCII 階層樹帶編號 | 選 (b) | 六個痛點有先后依賴關係（探測→抽取→pivot→反封鎖→產出），階層樹能呈現流程感 |
| 背景是否含 OSINT 歷史 | (a) 只講技術背景 (b) 加 OSINT 制度化歷史 | 選 (b) | 使用者問「為什麼會發生」，只講 API 關閉不足以回答；OSINT 從情報圈普及到一般人是需求側主因 |
| 線索強度排序是否納入 | (a) 省略 (b) 以階層呈現 | 選 (b) | 直接回答「為何 username 是 Maigret 切入點」——它在線索強度光譜中是「最常拿到但最難單獨利用」的位置 |
| SOWEL 頁面空內容處理 | (a) 改用 CDP (b) 以 URL 存在性 + README 明列 SOWEL 分類為佐證 | 選 (b) | SOWEL 頁為 JS render，webfetch 取不到正文，但 README 已明列 SOTL-2.2 / 6.2 分類名稱，足以佐證；依規則 CDP 僅在必要時使用 |
