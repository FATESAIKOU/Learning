# CSRF on Login Endpoint - No Anti-CSRF Token Required

**ID:** vuln-0008
**Severity:** MEDIUM
**Found:** 2026-07-14 08:06:55 UTC
**Target:** https://api.axross-recipe.com
**Endpoint:** /sessions
**Method:** POST
**CWE:** CWE-352
**CVSS:** 5.3

## Description

The login endpoint at POST /sessions on api.axross-recipe.com does not require any CSRF token, origin header check, or SameSite cookie validation. An attacker can craft a cross-origin HTML form that, when visited by a victim, silently attempts to log in with attacker-controlled credentials.

## Impact

An attacker can force a victim's browser to attempt authentication with attacker-controlled credentials. While the login itself would fail (wrong credentials), the request reveals the victim's IP address and user-agent to the attacker. More importantly, this CSRF vulnerability on the login endpoint demonstrates a systemic lack of CSRF protection across the API, increasing the risk for other state-changing operations.

## Technical Analysis

The login endpoint at POST /sessions on api.axross-recipe.com accepts JSON payloads with email_or_id and password fields. The endpoint returns 401 Unauthorized for invalid credentials, but does not require any CSRF token, Origin header, or Referer header validation. The endpoint is accessible without authentication. The API client (axios) sends requests with withCredentials: true, but the server does not validate the origin of the request.

## Proof of Concept

1. Send a POST request to https://api.axross-recipe.com/sessions with JSON data containing email_or_id and password fields. 2. No CSRF token or session cookie is required. 3. The endpoint returns 401 Unauthorized for invalid credentials, but the request is processed without CSRF validation.

```
import requests
url = "https://api.axross-recipe.com/sessions"
headers = {"Content-Type": "application/json"}
data = {"email_or_id": "test@test.com", "password": "wrongpassword"}
resp = requests.post(url, headers=headers, json=data)
print(f"Status: {resp.status_code}, Response: {resp.text}")
```

## Remediation

1. Implement CSRF protection on all state-changing API endpoints including login. 2. Validate the Origin and/or Referer headers on all state-changing requests. 3. Implement anti-CSRF tokens tied to the user session. 4. Use SameSite=Strict or SameSite=Lax cookies for session cookies.
