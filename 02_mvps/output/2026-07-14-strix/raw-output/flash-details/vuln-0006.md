# Open Redirect via NextAuth callbackUrl Parameter

**ID:** vuln-0006
**Severity:** MEDIUM
**Found:** 2026-07-14 08:06:23 UTC
**Target:** https://axross-recipe.com
**Endpoint:** /api/auth/signin
**Method:** GET
**CWE:** CWE-601
**CVSS:** 4.7

## Description

The NextAuth signin endpoint at /api/auth/signin accepts an arbitrary callbackUrl parameter without validating that the URL is on the same origin. The callback URL is stored in the __Secure-next-auth.callback-url cookie and used to redirect the user after successful authentication. An attacker can craft a link that, when clicked, sets the callback URL to an external domain, leading to an open redirect after authentication.

## Impact

An attacker can use this open redirect for phishing attacks. After a victim authenticates via Azure AD, they would be redirected to an attacker-controlled domain. This can be used to steal authentication tokens, credentials, or trick users into visiting malicious sites. The open redirect can also be chained with OAuth flows to intercept authorization codes.

## Technical Analysis

The NextAuth.js signin endpoint at /api/auth/signin accepts a callbackUrl query parameter. When an external URL is provided (e.g., https://evil.com), the server sets the __Secure-next-auth.callback-url cookie to the external URL and redirects the browser to /signin?callbackUrl=https://evil.com. After the user completes authentication via Azure AD, the callback URL from the cookie is used to redirect the user. NextAuth.js by default validates callback URLs against the configured allowed origins, but the server accepts external URLs without validation. The cookie is set with HttpOnly, Secure, and SameSite=Lax attributes, but the URL itself is not validated against an allowlist.

## Proof of Concept

1. Craft a URL: https://axross-recipe.com/api/auth/signin?callbackUrl=https://evil.com 2. When a victim visits this URL, the __Secure-next-auth.callback-url cookie is set to https://evil.com 3. The victim is redirected to /signin?callbackUrl=https://evil.com 4. If the victim authenticates via Azure AD, they would be redirected to https://evil.com after authentication

```
import requests
# Test the open redirect
url = "https://axross-recipe.com/api/auth/signin?callbackUrl=https://evil.com"
resp = requests.get(url, allow_redirects=False)
print(f"Status: {resp.status_code}")
print(f"Location: {resp.headers.get('Location')}")
for cookie in resp.cookies:
    print(f"Cookie: {cookie.name}={cookie.value}")
```

## Remediation

1. Validate the callbackUrl parameter against an allowlist of allowed origins. 2. Only allow relative paths or URLs on the same origin. 3. Implement a strict allowlist of callback URLs in the NextAuth configuration. 4. Consider using the NEXTAUTH_URL environment variable as the only allowed callback URL origin. 5. Add server-side validation that rejects callback URLs pointing to external domains.
