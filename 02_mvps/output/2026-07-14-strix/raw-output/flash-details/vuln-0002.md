# User Enumeration via Unauthenticated /users/{id} Endpoint

**ID:** vuln-0002
**Severity:** MEDIUM
**Found:** 2026-07-14 08:04:21 UTC
**Target:** https://api.axross-recipe.com
**Endpoint:** /users/{id}
**Method:** GET
**CWE:** CWE-200
**CVSS:** 5.3

## Description

The /users/{id} endpoint at api.axross-recipe.com returns user profile data without any authentication. This allows an attacker to enumerate all users on the platform by iterating through user IDs, collecting names, avatar URLs, and role information.

## Impact

An attacker can enumerate all registered users on the platform, collecting usernames, profile information, and role assignments. This information can be used for targeted phishing attacks, social engineering, username enumeration for credential stuffing, and identifying high-privilege users. The ability to distinguish between existing and non-existing user IDs also enables user enumeration attacks.

## Technical Analysis

The /users/{id} endpoint is a Rails API endpoint that returns user profile data without any authentication check. The endpoint returns a JSON object containing: id, name, avatar URL, introduction, role, and transferred status. Existing users return HTTP 200 with user data, while non-existing users return HTTP 404 with {"result":"not found"}. This difference in response codes enables automated user enumeration. The endpoint is accessible via a simple GET request with no authentication headers required.

## Proof of Concept

1. Send a GET request to https://api.axross-recipe.com/users/1
2. Observe the response contains user data (name, role, avatar URL)
3. Send a GET request to https://api.axross-recipe.com/users/999999
4. Observe the response returns {"result":"not found"}
5. The difference in responses allows automated user enumeration

```
#!/bin/bash
# Enumerate users by iterating through IDs
for id in 1 10 50 100 500 1000; do
  result=$(curl -s "https://api.axross-recipe.com/users/$id")
  name=$(echo "$result" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('name','NOT_FOUND'))" 2>/dev/null)
  echo "User $id: $name"
done
```

## Remediation

1. Add authentication checks to the /users/{id} endpoint to require authentication
2. Return consistent responses for both existing and non-existing users to prevent enumeration
3. Consider implementing rate limiting on user ID lookups
4. Review whether public user profiles need to expose the role field
