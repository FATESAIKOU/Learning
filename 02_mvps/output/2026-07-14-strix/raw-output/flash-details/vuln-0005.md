# CSRF on Password Reset Endpoint - No Anti-CSRF Token Required

**ID:** vuln-0005
**Severity:** MEDIUM
**Found:** 2026-07-14 08:06:13 UTC
**Target:** https://api.axross-recipe.com
**Endpoint:** /password_reset
**Method:** POST
**CWE:** CWE-352
**CVSS:** 5.3

## Description

The password reset endpoint at POST /password_reset on api.axross-recipe.com does not require any CSRF token, origin header check, or SameSite cookie validation. An attacker can craft a cross-origin HTML form that, when visited by a victim, silently triggers a password reset email to be sent to an arbitrary email address.

## Impact

An attacker can force a victim's browser to trigger password reset emails for arbitrary email addresses. This can be used for email bombing attacks, denial of service, or as a precursor to phishing attacks where the victim receives an unexpected password reset email from the legitimate service.

## Technical Analysis

The password reset endpoint at POST /password_reset on api.axross-recipe.com accepts JSON payloads with an email field. The endpoint returns {"result":"success"} for any email address. No CSRF token, Origin header, or Referer header validation is performed. The endpoint is accessible without authentication and without any session/cookie requirement. Additionally, there is no rate limiting on this endpoint, allowing an attacker to send unlimited password reset emails.

## Proof of Concept

1. Send a POST request to https://api.axross-recipe.com/password_reset with JSON data containing an email field. 2. No CSRF token or session cookie is required. 3. The endpoint returns {"result":"success"} indicating the password reset email was sent. 4. This can be triggered cross-origin from an attacker-controlled website.

```
import requests
url = "https://api.axross-recipe.com/password_reset"
headers = {"Content-Type": "application/json"}
data = {"email": "victim@example.com"}
resp = requests.post(url, headers=headers, json=data)
print(f"Status: {resp.status_code}, Response: {resp.text}")
```

## Remediation

1. Implement CSRF protection on the password reset endpoint. 2. Validate the Origin and/or Referer headers. 3. Implement rate limiting on password reset requests per email address and per IP. 4. Add CAPTCHA or similar challenge to prevent automated abuse. 5. Consider implementing a time-based one-time password (TOTP) or email verification step before sending the reset email.
