# CSRF on Signup Endpoint - No Anti-CSRF Token Required

**ID:** vuln-0004
**Severity:** MEDIUM
**Found:** 2026-07-14 08:06:05 UTC
**Target:** https://api.axross-recipe.com
**Endpoint:** /signup
**Method:** POST
**CWE:** CWE-352
**CVSS:** 5.3

## Description

The signup endpoint at POST /signup on api.axross-recipe.com does not require any CSRF token, origin header check, or SameSite cookie validation. An attacker can craft a cross-origin HTML form that, when visited by a victim, silently submits a registration request to create a new user account.

## Impact

An attacker can force a victim's browser to create a user account on Axross Recipe without the victim's knowledge or consent. This can be used for account creation spam, phishing setups, or as a precursor to other attacks.

## Technical Analysis

The signup API endpoint at POST /signup on api.axross-recipe.com accepts JSON payloads with name, email, and password fields. The endpoint returns {"result":"success"} for valid registration data. No CSRF token, Origin header, or Referer header validation is performed. The NextAuth.js CSRF protection (__Host-next-auth.csrf-token cookie) is only used for NextAuth-specific endpoints, not for the application's own API endpoints on api.axross-recipe.com.

## Proof of Concept

1. Send a POST request to https://api.axross-recipe.com/signup with JSON data containing name, email, and password fields. 2. No CSRF token or session cookie is required. 3. The endpoint returns {"result":"success"} indicating the account was created.

```
import requests
url = "https://api.axross-recipe.com/signup"
headers = {"Content-Type": "application/json"}
data = {"name": "csrf_test", "email": "csrf_test@test.com", "password": "TestPass123!"}
resp = requests.post(url, headers=headers, json=data)
print(f"Status: {resp.status_code}, Response: {resp.text}")
```

## Remediation

1. Implement CSRF protection on all state-changing API endpoints. 2. Validate the Origin and/or Referer headers on all state-changing requests. 3. Implement anti-CSRF tokens tied to the user session. 4. Use SameSite=Strict or SameSite=Lax cookies for session cookies.
