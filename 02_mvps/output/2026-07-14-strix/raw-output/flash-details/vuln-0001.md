# Information Disclosure via Unauthenticated /configs Endpoint

**ID:** vuln-0001
**Severity:** HIGH
**Found:** 2026-07-14 08:04:08 UTC
**Target:** https://api.axross-recipe.com
**Endpoint:** /configs
**Method:** GET
**CWE:** CWE-200
**CVSS:** 7.5

## Description

The /configs endpoint at api.axross-recipe.com returns sensitive internal configuration data without any authentication. This includes organization IDs, JupyterHub access lists, recipe creation permissions, comment-restricted organizations, terms update timestamps, and internal database coexistence comments.

## Impact

An attacker can enumerate internal organization IDs, identify which organizations have JupyterHub access, which can create recipes, and which have restricted commenting. This information can be used to target specific organizations, understand the internal structure of the platform, and plan further attacks. The leaked organization IDs (37, 53, 180, 557, 629, 639 for JupyterHub; 37, 53, 131, 56, 142, 211, 531, 944, 986, 1009, 1085 for recipe creation) provide a direct attack surface for targeted phishing or privilege escalation attempts.

## Technical Analysis

The /configs endpoint is a Rails API endpoint that returns all application configuration records without any authentication check. The endpoint returns an array of config objects, each containing: id, key, value, created_at, updated_at, transferable, virtual_id, virtual_params, config_type, value_json, and available_in_client. Sensitive data exposed includes: jupyterhub_orgs (organization IDs with Jupyter access), create_recipe_orgs (organization IDs that can create recipes), ng_comment_orgs (organization IDs with restricted commenting), coexist_db_comments (internal notes about database coexistence), and common_updated_terms_at (terms update timestamp). The endpoint is accessible via a simple GET request with no authentication headers required.

## Proof of Concept

1. Send a GET request to https://api.axross-recipe.com/configs
2. Observe the response contains all application configuration data
3. No authentication headers or session cookies are required

```
curl -s https://api.axross-recipe.com/configs | python3 -m json.tool
```

## Remediation

1. Add authentication checks to the /configs endpoint to ensure only authenticated users with appropriate permissions can access it
2. Review which config fields need to be exposed to the client (available_in_client flag) and restrict sensitive data
3. Implement proper authorization checks for all configuration endpoints
4. Consider using a separate, authenticated admin endpoint for sensitive configuration data
