# Missing Rate Limiting on Authentication and Password Reset Endpoints

**ID:** vuln-0007
**Severity:** MEDIUM
**Found:** 2026-07-14 08:06:32 UTC
**Target:** https://api.axross-recipe.com
**Endpoint:** /signup, /password_reset
**Method:** POST
**CWE:** CWE-770
**CVSS:** 5.3

## Description

The signup endpoint (POST /signup) and password reset endpoint (POST /password_reset) on api.axross-recipe.com have no rate limiting. An attacker can send unlimited concurrent requests to these endpoints without any throttling or IP-based restrictions.

## Impact

An attacker can: 1. Create unlimited user accounts (account creation spam). 2. Send unlimited password reset emails to a target email address (email bombing). 3. Perform brute-force attacks on the login endpoint without rate limiting. 4. Exhaust server resources through rapid requests (denial of service).

## Technical Analysis

Testing confirmed that 10 concurrent requests to the signup endpoint all returned {"result":"success"} without any throttling. Similarly, 5 rapid requests to the password reset endpoint all returned success. No rate limiting headers (X-RateLimit-*) were observed in the responses. The server does not implement IP-based rate limiting, token bucket algorithms, or any other throttling mechanism on these endpoints.

## Proof of Concept

1. Send 10 concurrent POST requests to https://api.axross-recipe.com/signup 2. All 10 requests return {"result":"success"} 3. Send 5 rapid POST requests to https://api.axross-recipe.com/password_reset 4. All 5 requests return {"result":"success"} 5. No rate limiting is observed

```
import concurrent.futures
import requests

def test_signup(i):
    url = "https://api.axross-recipe.com/signup"
    data = {"name": f"ratetest{i}", "email": f"ratetest{i}@test.com", "password": "TestPass123!"}
    resp = requests.post(url, json=data)
    return f"Request {i}: Status={resp.status_code}"

with concurrent.futures.ThreadPoolExecutor(max_workers=10) as executor:
    futures = [executor.submit(test_signup, i) for i in range(10)]
    for future in concurrent.futures.as_completed(futures):
        print(future.result())
```

## Remediation

1. Implement rate limiting on all authentication and password reset endpoints. 2. Use IP-based rate limiting (e.g., 5 requests per minute per IP). 3. Implement account-based rate limiting (e.g., 3 password reset requests per hour per email). 4. Add CAPTCHA or similar challenge for signup and password reset flows. 5. Consider using a token bucket or sliding window algorithm for rate limiting. 6. Return appropriate HTTP status codes (429 Too Many Requests) with Retry-After headers when rate limits are exceeded.
