# Open Redirect in OAuth callbackUrl Parameter

**ID:** vuln-0002
**Severity:** MEDIUM
**Found:** 2026-07-14 08:34:36 UTC
**Target:** https://axross-recipe.com/api/auth/signin
**Endpoint:** /api/auth/signin
**Method:** GET
**CWE:** CWE-601
**CVSS:** 6.1

## Description

The NextAuth.js OAuth signin endpoint accepts an arbitrary callbackUrl parameter without proper validation. After successful authentication via Google OAuth, the user is redirected to whatever URL was specified in the callbackUrl parameter. This allows attackers to redirect victims to malicious sites after they authenticate.

## Impact

An attacker can craft a link that appears to go to the legitimate Axross Recipe login page but redirects the victim to an attacker-controlled site after authentication. This can be used for phishing attacks, OAuth token theft, or credential harvesting. The attack is particularly effective because the initial URL is on the trusted axross-recipe.com domain.

## Technical Analysis

The NextAuth.js configuration does not restrict the callbackUrl parameter. When a user initiates OAuth sign-in via /api/auth/signin?callbackUrl=..., the server stores the provided URL in the __Secure-next-auth.callback-url cookie without validation. After the OAuth flow completes, NextAuth.js redirects the user to this stored URL. The only blocked scheme is javascript:, but all HTTP/HTTPS URLs are accepted regardless of domain. This is a classic open redirect vulnerability in the OAuth flow.

## Proof of Concept

1. Craft a URL: https://axross-recipe.com/api/auth/signin?callbackUrl=https://evil.com
2. The server sets __Secure-next-auth.callback-url cookie to https://evil.com
3. After the user authenticates via Google OAuth, they are redirected to evil.com
4. The attacker's site can capture OAuth tokens or present a fake interface

Multiple bypass techniques were confirmed:
- Direct external URL: callbackUrl=https://evil.com
- Protocol-relative: callbackUrl=//evil.com
- Subdomain bypass: callbackUrl=https://axross-recipe.com.evil.com
- Userinfo bypass: callbackUrl=https://axross-recipe.com@evil.com

```
#!/usr/bin/env python3
"""Open Redirect PoC for Axross Recipe OAuth callbackUrl"""
import requests

BASE = "https://axross-recipe.com/api/auth/signin"

# Test various redirect payloads
payloads = [
    "https://evil.com",
    "//evil.com",
    "https:evil.com",
    "https://axross-recipe.com.evil.com",
    "https://axross-recipe.com@evil.com",
]

for payload in payloads:
    url = f"{BASE}?callbackUrl={payload}"
    resp = requests.get(url, allow_redirects=False)
    
    # Check if the callback URL was accepted
    for cookie in resp.cookies:
        if 'callback-url' in cookie.name:
            print(f"Payload: {payload}")
            print(f"  Cookie set: {cookie.name}={cookie.value}")
            print(f"  VULNERABLE: callback URL accepted")
            break
    else:
        print(f"Payload: {payload} - REJECTED")
```

## Remediation

1. Implement a strict allowlist of permitted callback URLs in the NextAuth.js configuration.
2. Only allow callback URLs that match the application's domain (axross-recipe.com).
3. Configure NextAuth.js with a whitelist of allowed callback URLs rather than accepting any URL.
4. Validate the callback URL against the allowed list before setting the cookie.
5. Consider using relative URLs only for the callback, or hardcoding the callback path.
