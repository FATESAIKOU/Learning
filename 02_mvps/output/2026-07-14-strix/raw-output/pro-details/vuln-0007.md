# Missing Rate Limiting on Authentication Endpoints

**ID:** vuln-0007
**Severity:** CRITICAL
**Found:** 2026-07-14 08:35:53 UTC
**Target:** https://api.axross-recipe.com/sessions
**Endpoint:** /sessions
**Method:** POST
**CWE:** CWE-307
**CVSS:** 9.1

## Description

The login endpoint at api.axross-recipe.com/sessions and the NextAuth.js callback at axross-recipe.com/api/auth/callback/credentials have no rate limiting protection. Ten rapid consecutive authentication attempts were all processed without any throttling or lockout, returning HTTP 401 rather than HTTP 429 (Too Many Requests).

## Impact

An attacker can perform unlimited brute-force attacks against user accounts without being blocked or rate-limited. Combined with the weak password policy (no minimum strength requirements), this makes credential guessing attacks highly feasible. An attacker could systematically test common passwords against known email addresses to compromise user accounts.

## Technical Analysis

The Rails API backend at /sessions processes authentication requests without any apparent rate limiting mechanism. Ten rapid POST requests with different credentials all returned HTTP 401 with the same response body, indicating no account lockout, no IP-based throttling, and no progressive delay. The NextAuth.js callback endpoint similarly returned HTTP 400 for all rapid attempts without any 429 responses. The absence of rate limiting on authentication endpoints is a fundamental security control gap.

## Proof of Concept

1. Send 10 rapid POST requests to /sessions with different credentials
2. All 10 requests return HTTP 401 (not 429)
3. No delay, no lockout, no CAPTCHA challenge
4. Same behavior observed on NextAuth.js callback endpoint

```
import requests
import time

API = "https://api.axross-recipe.com"
HEADERS = {"Content-Type": "application/json", "Origin": "https://axross-recipe.com"}

print("Testing rate limiting on /sessions endpoint...")
for i in range(10):
    start = time.time()
    r = requests.post(f"{API}/sessions", headers=HEADERS, json={
        "session": {
            "email": f"bruteforce_test{i}@example.com",
            "password": "wrongpassword"
        }
    })
    elapsed = time.time() - start
    print(f"Attempt {i+1}: HTTP {r.status_code} ({elapsed:.2f}s)")
    if r.status_code == 429:
        print("  -> Rate limiting detected!")
        break
else:
    print("\nNo rate limiting detected - all 10 attempts processed without throttling")
```

## Remediation

1. Implement IP-based rate limiting on authentication endpoints (e.g., 5 attempts per minute per IP)
2. Implement account-based lockout after consecutive failed attempts (e.g., 5 failed attempts = 15-minute lockout)
3. Add progressive delay between failed attempts (exponential backoff)
4. Consider adding CAPTCHA after multiple failed attempts
5. Use a dedicated rate-limiting middleware like rack-attack for Rails applications
6. Log and monitor failed authentication attempts for anomaly detection
