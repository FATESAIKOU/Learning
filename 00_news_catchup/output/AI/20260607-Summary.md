## 外部狀況總結

2026 年 6 月的 AI 業界呈現「**企業 AI 整合進入深水區**」的三條主軸:

1. **框架抽象層穩定** — Spring AI 2.0 統一 tool calling、Cloudflare 收購 VoidZero 整合 Rolldown/Oxc/Vite 工具鏈,意味著「AI 應用框架」從 1.x 試錯期進入收斂期。Rails 端尚無對標產品 (LangChain.rb 進展緩慢),**這是商機**。

2. **AI 安全從理論走到實戰** — CVE-2026-49975 HTTP/2 Bomb 由 OpenAI Codex 發現,標誌「AI 找 bug」進入主流;但同時 McDonald's AI Drive-Thru 失敗顯示「AI 替換人際互動」會產生公關風險; Illinois/Ohio 暫停 data center 稅補貼,NY 通過 data center 暫停令,顯示**AI 基礎設施的政治成本正在具現化**。

3. **Agent 平台層 (AgentCore/Cloudflare) 開始搶 SaaS 入口** — Google Universal Cart 結合 AI 自動找商品,繞過 Amazon 商品頁;AWS AgentCore Skills 機制讓企業自定義 agent 流程。**這對 AxrossRecipe 既是機會 (新創可建 agent marketplace) 也是威脅 (Google/AWS 自己做掉)**。

## 2 個最值得深入 catchup

### 技術面: Spring AI 2.0.0-RC1 Available Now
- **為何選這篇**: 你未來管理 Spring 團隊,或要在 Rails 棧做 AI 整合時,Spring AI 的 ToolCallingAdvisor / VectorStoreAdvisor / MCP SDK 2.0 整合模式是最成熟的 Java 借鑑
- **深入方式**:
  1. clone Spring AI repo,跑 samples 改一個 custom ToolCallback 確認遷移影響
  2. 比較 Spring AI Tool Calling 抽象 vs LangChain.rb / Ruby OpenAI gem 的差異
  3. 評估 MCP SDK 2.0 是否能在你現有 Axross 專案引入 (內部 wiki/issue 系統加 MCP server)
  4. 訂閱 Spring 官方 blog 與 github release notes,追蹤 2.0 GA 推出日期

### 產業/政治面: Cloudflare supports Vite's mission
- **為何選這篇**: Cloudflare 收購 VoidZero =「CDN 巨頭 × AI 工具鏈新創」,將影響 Vite/Rolldown/Oxc 走向,進一步影響你 RoR+Svelte+Vite+Turbo 棧的 bundler 選擇 (目前 Vite 8 → Vite 9 Environment API 穩定化)
- **深入方式**:
  1. 讀 VoidZero 與 Cloudflare 雙方 blog post 完整版,理解 1M 開源基金分配邏輯
  2. 在你現有 Axross 專案跑一次 Vite 8 + Rolldown 全 bundle 模式,確認 build 時間改善
  3. 觀察 Cloudflare Workers 對 Vite SSR 的整合 (影響你若做 SaaS 邊緣部署)
  4. 與團隊內討論:我們若做新創,工具鏈中立性 vs 單一雲廠商綁定的取捨
