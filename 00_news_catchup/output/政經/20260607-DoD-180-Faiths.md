# 07. DOD Officially Drops 180 Faiths From Military's Recognized Religion List (原文)

**Source**: https://www.military.com/dod-officially-drops-180-faiths-from-militarys-recognized-religion-list
**Author**: Nick Mordowanec (Military.com)
**Date**: 2026/06/04
**Category**: 政治經濟

## 1. 這個政策解決什麼問題?

美國國防部(DoD,2026 年因 Department of War 更名爭議暫稱 DoW)將「認可宗教清單 (Religious Affiliation Codes)」從 211 個精簡至 31 個,並刪除約 180 個少數信仰/世界觀類別,同步要求 60 天內完成資料庫與表單更新。

| 面向 | 政策目標 |
|---|---|
| 後勤/制度面 | 牧師團 (Chaplaincy) 對服務成員的宗教支援對應關係更清晰 |
| 行政面 | 終結「over-specific 信仰編碼」導致的統計、預算、徽章/Tech 標籤混亂 |
| 政治面 | 落實國防部長 Hegseth「streamline religious preferences collection」之政策意圖 |
| 憲法面 | 維持「志願者宗教選擇自由」+「軍隊不設立宗教」雙軌 (成員仍可選清單外,僅是 dog tag 預設欄位受限) |

## 2. 這個問題為什麼會發生?(背景)

### 美軍「認可宗教清單」的歷史定位

| 時期 | 演進 |
|---|---|
| 1775 | 國會授權陸軍招募牧師,確認隨軍宗教服務制度 |
| 1863 | 國防部前身 War Department 統一牧師團制服與徽章制度 |
| 二戰後 | 隨牧師團專業化,宗教代碼開始用於統計與預算配置 |
| 越戰後 | 多元信仰入伍,代碼膨脹 |
| 2017-03-27 | 上次修正備忘錄,211 個代碼定型(Obama 末期到 Trump 1.0 過渡) |
| 2026-05-20 | Tata 副部長簽署 60 天內執行 31 個代碼,清掉 180 個 |

> 推測:代碼膨脹本身反映「美軍內部世俗化、多元化、新興宗教運動 (NRM) 興起」之社會變遷,2026 大幅瘦身可視為「官僚系統回頭追上社會現實」。

### 為何此時出手?

1. 行政命令節奏:Hegseth(2025 年初就任)上任後推動 DoD 行政瘦身
2. 信仰類型分布懸殊:被刪除的 Atheist / Pagan / Wiccan / Asatru / Humanist 等合計人數極少(推測總和 < 服役人員 1%),行政成本/代表性比例失衡
3. 數位化牧師調度系統:雲端資料庫讓「清單外手動輸入」成本大幅降低,刪除小眾代碼的副作用可控

## 3. 這個政策是如何解決該問題的?

### 核心機制:分類學 (Taxonomy) 重設計

| 變更 | 1.x 設計 | 2.0 設計 |
|---|---|---|
| 類別總數 | 211 | 31 |
| 主導邏輯 | 個別教派 (Baptist / Methodist / Lutheran / 個別佛教分支等) | 宗教 + 重要分支,其他歸入「Other」 |
| 個體自由 | 只能選清單內 | 仍可填清單外,僅在 dog tag 預設欄位使用新代碼 |
| 配套 | 各教派代碼獨立計算預算 | 牧師團依「總信仰家族」彈性調度 |

### 31 個保留類別的結構

- **世界觀類**:Agnostic, No Religion, Other Religions
- **東方系**:Buddhism, Hindu, Sikh
- **一神教系**:Baha'i, Islam, Judaism
- **基督教 17 分支**:Catholic, Baptist, Methodist, Lutheran, Presbyterian, Orthodox, Pentecostal, etc.
- **預設桶**:Christian - Other, Christian - Non Denominational

### 配套政策:60 天落地

- 5/20 備忘錄下發 → 7/19 前完成所有資料庫、enlistment 表單、ID 卡系統更新
- Chaplaincy 仍可依「family-level」調度(例:全基督教共用牧師池)
- 推測:資料庫採用 flexible code + 自由文字欄位,避免下次又膨脹

## 4. 是否存在解決類似問題的其他技術 / 框架 / 思考方式?

| 替代方案 | 機制 | 優點 | 缺點 | 適用情境 |
|---|---|---|---|---|
| **完全自由文字欄位 (Open-text)** | 取消預設清單,僅留 free input | 零歧視、零行政負擔 | 無法做統計、無法精準調度牧師 | 小型組織、人數 < 1,000 |
| **階層式分類 (Hierarchical ontology)** | 1→多 mapping,例:Christian → Baptist → Southern Baptist | 兼顧精細與統計 | 維護成本高、命名衝突 | 大型資料集,需跨單位分析 |
| **三層制 (Tier system)** | 上層宗教 (3 個) / 中層教派 (30 個) / 下層文化變體 (自由) | 統計友善 + 個體自由 | 教牧人員需理解層級 | 推測:英、加、澳軍隊採用 |
| **不收集 (No collection)** | 全面禁止宗教資料收集 | 絕對中立 | 牧師團無法配對、預算無法編 | 推測:部分北歐國家 |
| **2026 DoD 31-code 方案** | 精簡 + 自由填寫雙軌 | 平衡行政效率與個體自由 | 小眾信仰在 dog tag 預設不可見 | 推測:最適合大型、多元、預算有限的軍隊 |

### 對 IT 治理的類比啟示

- **分類系統 (taxonomy) 維護** 與 **資料 schema 演進** 高度同構:每隔 5-10 年要「正視債務」,否則無限膨脹
- **自由文字 + 預設 bucket** 雙軌設計,可借鏡到 enum 設計、角色權限矩陣
- **60 天 transition period** 是大型資料系統遷移的合理時程(DDL + 應用 + 文件 + 教育訓練)
- 管理者身分啟示:跨宗教牧師團的「family-pool 調度」與企業「cross-functional squad」概念類似
