## 2 篇最值得深入 catchup (跨類別, 1 技術面 + 1 產業/政治面)

### 技術面: Spring AI 2.0.0-RC1 Available Now
- **為何選這篇**: 你未來管理 Spring 團隊可能性高,或要在 Rails 棧做 AI 整合時,Spring AI 的 ToolCallingAdvisor / VectorStoreAdvisor / MCP SDK 2.0 整合模式是最成熟的 Java 借鑑;若能在 2.0 GA 前完成 PoC,將是 Softbank 內部 AI 整合知識領導者。
- **深入方式**:
  1. **clone + run samples**: `git clone https://github.com/spring-projects/spring-ai`,跑官方 samples 確認 2.0 API,特別是 `ToolCallingAdvisor` 與 `ChatClient.entity(EntityParamSpec)`
  2. **做一個 PoC**: 在你 Axross 專案內,用 Spring AI 2.0 寫一個「內部 wiki 問答 Bot」,串接 Spring AI Vector Store + Claude API,證明 RAG 可行
  3. **cross-stack 對照**: 寫一份內部 memo「Spring AI 2.0 vs LangChain.rb 對比」,評估 RoR 棧的 AI 整合路徑
  4. **追蹤 2.0 GA**: 訂閱 github.com/spring-projects/spring-ai releases,目標在 GA 後 2 週內完成你專案的升版評估
  5. **社群交流**: 加入 Spring AI GitHub Discussions,提問 / 回答 1 個 thread,建立外部可見度

### 產業/政治面: Illinois joins Ohio in Ordering Pause on Data Center Tax Credits
- **為何選這篇**: 兩州 (一民主黨一共和黨) 同時暫停 AI data center 稅補貼,顯示**AI 基建政治化**已從理論進入實戰;若 Softbank 投資 AI 基建類新創 (data center, GPU cloud, edge compute), 這是**估值模型必須立刻重算**的政策紅燈,影響你所有 AI infra 投資判斷。
- **深入方式**:
  1. **讀原始文件**: 通讀 Fortune 原報導 + Pritzker 行政命令原文 + Ohio 立法文本,理解具體政策條款 (哪些 data center 類型被排除, 暫停到何時, 是否有新稅)
  2. **跨州對照**: 比較 Texas (共和黨, 仍補貼) vs Illinois/Ohio (兩黨, 暫停) 的 data center 招商策略,看哪些州可能跟進
  3. **內部投資判斷**: 與 Softbank 投資部同事討論:州級政策對 AI 基建類新創 exit 估值的 discount 應該多少;現有 portfolio 中有幾家受影響
  4. **追蹤後續**: 訂閱 NGA (National Governors Association) 與 NARUC (州級公用事業委員會) 報告,追蹤下個州的暫停行動
  5. **對日本的鏡像思考**: 觀察日本地方政府 (東京都 / 大阪府) 是否會有類似政策; Softbank Energy 在日本的 AI 基建投資是否需重新評估
