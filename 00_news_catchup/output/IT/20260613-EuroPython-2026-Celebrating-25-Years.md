# 01. Real Python: The Real Python Podcast – Episode #299: EuroPython 2026: Celebrating 25 Years

**Source**: https://realpython.com/podcasts/rpp/299/
**Author**: Christopher Bailey (Host), Mia Bajić & Daria Linhart Grudzien (Guests)
**Date**: 2026-06-13
**Category**: 傳統IT技術

## 1. この技術/政策は何を解決するのか?

EuroPython 2026 は、Python コミュニティの知識共有、ネットワーキング、およびエコシステムの持続的発展という三つの課題を同時に解決する場である。

| 解決する課題 | 具體手段 |
|-------------|---------|
| 知識の斷片化 | 多様なトラック（Web、データサイエンス、DevOps、教育など）による橫斷的學習 |
| コミュニティの孤立 | 25 年の歴史を持つカンファレンスが形成する信頼ネットワーク |
| エコシステムの方向性喪失 | コア開発者・ライブラリ作者・ユーザー間の直接対話によるロードマップ共有 |

Python エコシステムは約 50 萬の PyPI パッケージを擁し、データサイエンスから Web 開發、組み込みまで領域が急擴張している。この多様化は「どのライブラリを選ぶべきか」「どの設計パターンがベストプラクティスか」という判斷コストを急増させた。EuroPython は 1 週間の集中したセッション、BoF（Birds of a Feather）、スプリントを通じて、この情報非対稱を解消する。

## 2. この問題が発生する背景は?

Python が直面するコミュニティ課題の背景には、以下の構造的要因がある。

**第一に、Python の適用領域の爆発的拡大**。2010 年代は Web 開發（Django/Flask）と科學計算（NumPy/SciPy）が二大柱だったが、2020 年代に入り ML/AI（PyTorch, JAX, HuggingFace）、データエンジニアリング（Polars, DuckDB）、非同期プログラミング（asyncio, FastAPI）、WebAssembly（Pyodide）と領域が細分化した。各領域のベストプラクティスは獨立に進化し、橫斷的な知見共有が困難になっている。

**第二に、リモートワークの定著による対面交流の減少**。COVID-19 以降、多くの開発者がリモートワークに移行し、地域ミートアップの參加率が低下した。オンラインフォーラム（Discord, Zulip, Discourse）は情報交換を支えるが、信頼構築や偶発的なコラボレーション創出には対面が優位である。

**第三に、Python のコア開発とユーザー層の乖離**。CPython の Steering Council やコア開発者は數十人規模だが、ユーザーは數千萬人に達する。PEP の議論は主に discuss.python.org で行われるが、大多數のユーザーはこのプロセスを認知していない。EuroPython はコア開発者と一般ユーザーが直接対話できる數少ない場である。

## 3. この技術/政策はどのようにその問題を解決するのか?

EuroPython 2026 は以下のメカニズムでコミュニティ課題に対処する。

**多様なトラック設計による橫斷的學習**：
EuroPython 2026 のトラックは、Web フレームワーク、データサイエンス、DevOps/インフラ、教育・コミュニティ運營、言語內部（型ヒント、パフォーマンス）、ハードウェア/組み込みなどに及び、參加者は自身の専門外のセッションにもアクセスできる。これにより「データサイエンティストが Web 開發のテスト戦略を學ぶ」「Web 開發者が C 拡張のメモリ管理を理解する」といったクロスドメイン學習が促進される。

**スプリントによる実踐的コラボレーション**：
カンファレンス最終日に開催されるスプリントでは、參加者がオープンソースプロジェクトに直接貢獻する。初心者はメンテナから直接指導を受け、メンテナは新たな貢獻者を獲得する。これは「貢獻したいが方法がわからない」という參入障壁を除去する。

**ボランティアと運營の持続モデル**：
EuroPython Society は非營利組織として、ボランティアベースの運營を 25 年間維持してきた。Mia Bajić（副議長）と Daria Linhart Grudzien（コミュニケーション責任者）が語るように、カンファレンスの持續的成長には「知識の引き継ぎ」「多様なバックグラウンドの運營メンバー確保」「スポンサーとの健全な関係構築」が鍵となる。このモデルは他の地域カンファレンス（PyCon US, PyCon JP, PyCon TW など）にも橫展開されている。

**開催地選定の戦略的意義**：
2026 年の開催地クラクフ（ポーランド）は、中東歐の Python コミュニティへのアクセスを提供する。西歐に集中しがちなテックカンファレンスの地理的偏りを緩和し、ポーランド、チェコ、ウクライナ、バルト諸國などの開発者に參加機會を提供する。

## 4. 類似の問題を解決する他の技術/フレームワーク/考え方は存在するか?

大規模コミュニティの知識共有とネットワーキングを解決するアプローチは複數存在する。

| アプローチ | 代表例 | 長所 | 短所 |
|-----------|--------|------|------|
| 大規模カンファレンス | EuroPython, PyCon US, FOSDEM | 橫斷的學習、信頼構築 | コスト・地理的制約 |
| 地域ミートアップ | PyLadies, Python User Groups | 低コスト、高頻度 | スケールしない、専門性に偏り |
| オンラインフォーラム | discuss.python.org, Discord | 非同期、グローバル | 信頼構築が弱い、炎上リスク |
| バーチャルカンファレンス | PyCon Online 2020-2021 | 地理的制約なし | 偶発的交流が困難 |
| メンターシッププログラム | Google Summer of Code, Outreachy | 構造化された貢獻パス | 対象者が限定される |
| 企業內トレーニング | 社內 Tech Talk, ハッカソン | 業務との統合 | 外部知見が入らない |

EuroPython の獨自性は、これらを「1 週間の集中イベント」に統合する點にある。特にスプリントは、オンラインフォーラムやバーチャルカンファレンスでは再現が難しい「対面でのペアプログラミングによる貢獻」を実現する。

Python エコシステムのもう一つの參照點として、Rust コミュニティの RustConf や RustFest がある。Rust コミュニティは「RFC プロセス」による言語進化の透明性で知られるが、Python の PEP プロセスも同等の機能を持つ。違いは、Python コミュニティがカンファレンスを「PEP の議論の場」としても活用する點にある。

また、企業主催の開発者カンファレンス（AWS re:Invent, Google Cloud Next）は製品プロモーションが主目的であり、コミュニティ主導の EuroPython とは根本的に性質が異なる。EuroPython の非營利・コミュニティ主導モデルは、ベンダーニュートラルな知見共有を可能にする點で、企業カンファレンスでは代替できない。
