# 09. 【デブサミ夏〆切はいよいよ明日！】2026年後半何を作り、何を任せるか？

**Category**: 傳統IT技術

## 1. 這個技術/政策解決什麼問題?

Developers Summit 2026 Summer（デブサミ夏）是一場以「エンジニアの事業貢献」為主題的技術會議，核心命題是：**2026 年後半，工程師該做什麼（何を作り）、該把什麼交出去（何を任せるか）？** 會議透過多場演講探討 AI 時代下工程師角色的轉變——從「自己寫 code」到「設計 + 委派（給 AI agent / 團隊）」。

## 2. 這個問題為什麼會發生?(背景)

### AI Coding 工具的普及

2026 年，GitHub Copilot、Cursor、Claude 等 AI coding 工具已從「輔助」進化為「可獨立完成任務的 agent」。這引發了工程師的 existential question：

```
傳統模式：  工程師 = 需求理解 → 設計 → 實作 → 測試 → 部署
AI 時代：   工程師 = 需求理解 → 設計 → 委派(AI/團隊) → 驗證 → 部署
                       ↑              ↑
                    核心價值不變    執行方式巨變
```

## 3. 這個技術/政策是如何解決該問題的?

### 主要セッションとテーマ分類

```
「作る」側のセッション（技術・產品）
├── AI Agentと『伴走』する開発プロセス
│   SREと開発チームのソフトウェア開発ライフサイクルの変化
│   (DMM.com 周昆琦氏、New Relic 小林良太郎氏)
│
├── AI時代の開発生産性は、個人技からチーム設計へ

└── エンジニアの事業目線は、本当に求められているのか？
    (Joystruct 佐藤大典氏、柄沢聡太郎氏、キャディ 藤倉成太氏、BASE 柳川慶太氏)

「任せる」側のセッション（管理・組織）
├── エンジニアに求められる"プロダクト全域"への越境
│   市場・予算・マーケ・法務まで「決める」と「任せる」を使い分ける技術
│   (Newbee 蜂須賀大貴氏)
│
├── さまざまな業界で輝くCTO 十人十色の役割と事業貢献
│   (イオン 山﨑賢氏、サグリ 牧野直矢氏、Fairy Devices 藤野真人氏)
│
└── 我々はどう生きるか
    (グリーホールディングス 藤本真樹氏)
```

### 核心主題矩陣

| | 技術面 | 組織/管理面 |
|------|--------|------------|
| **作る（Build）** | AI agent との伴走開発、チーム設計としての生產性 | エンジニアの事業目線 |
| **任せる（Delegate）** | AI に任せる範囲の線引 | CTO の役割進化、プロダクト全域への越境 |

### 關鍵訊息

1. **「個人技からチーム設計へ」**：AI 時代的開發生產力不再是個人 coding 速度，而是如何設計團隊（人+AI agent）的協作流程
2. **「決める」と「任せる」の使い分け**：工程師需跨域到市場、預算、法務，核心能力是判斷「什麼自己決定、什麼委派出去」
3. **「プロダクト全域への越境」**：工程師角色從「実装者」擴張到「產品全生命週期的決策者」

## 4. 是否存在解決類似問題的其他技術 / 框架 / 思考方式?

| 方案/會議 | 地區 | 焦點 | 與デブサミ的差異 |
|-----------|------|------|-----------------|
| **DevOps Days Tokyo** | 日本 | CI/CD、SRE 實踐 | 偏基礎設施，少談 AI agent |
| **QCon / InfoQ** | 全球 | 軟體架構與技術趨勢 | 偏技術深度，少談工程師角色轉變 |
| **Gartner IT Symposium** | 全球 | CIO/CTO 層級策略 | 偏管理層，少一線工程師視角 |
| **RubyKaigi / RubyConf** | 日本/全球 | Ruby 語言與生態 | 語言特定，非跨語言角色討論 |
| **AWS re:Invent / Google Next** | 全球 | 雲端服務 | 產品發布導向，非工程師職涯 |

**思考方式**：デブサミ的獨特定位是「日本工程師的職涯與角色轉變」——它不討論特定技術的 deep dive，而是討論「工程師在 AI 時代該如何重新定位自己」。這與西方技術會議的「工具/框架/架構」焦點形成互補。

**對用戶的意義**：用戶正在從 IC (Individual Contributor) 轉向管理角色（數月後成為 AxrossRecipe 部分機能的開發時程管理者）。デブサミ的主題——「何を作り、何を任せるか」——與用戶的職涯轉折點高度重合。特別是以下 session 直接相關：

- **「決める」と「任せる」を使い分ける技術**：用戶即將面臨的日常決策
- **AI 時代の開発生産性は、個人技からチーム設計へ**：用戶從 Scrum Master 到管理者的自然延伸
- **エンジニアに求められる"プロダクト全域"への越境**：用戶在 AxrossRecipe 的「商務策定支援」角色
